# AI-First TDD Philosophy

## Philosophy of AI-First TDD
1. **No More Red-Green-Refactor, But Generate Best Code**: AI generates the best code from the start.
2. **Code is Black Box, Test is Trust**: To the developer, AI code is a black box. Tests are the only basis for trust.
3. **Maximum Coverage = Maximum Confidence**: The more cases covered, the greater the confidence.

## Test Guidelines

### Unit Test
- **Purpose**: Verify that individual functions generated by AI work according to specification
- **Target**: Primitives, Domain layers
- **Principles**:
  - All public functions must be tested (the smallest unit of a black box)
  - Confirm robustness of AI code through edge cases
  - Tests serve as specifications: the name alone should convey the behavior

### Integration Test
- **Purpose**: Verify that AI-generated modules remain trustworthy when combined
- **Target**: Application, Infrastructure layers
- **Principles**:
  - Verify the entire UseCase flow
  - Confirm AI code's error handling through failure scenarios
  - Isolate external dependencies with Mock/Stub

### E2E Test
- **Purpose**: Final verification that the entire black box behaves according to user scenarios
- **Target**: Full system based on CLI Client
- **Principles**:
  - Cover happy path + major failure scenarios
  - Use settings similar to the real environment
  - If this test passes, it is safe to deploy

## Coverage Standards

### Target Coverage
- **Core (Primitives/Domain/Application)**: 100% (core business logic)
- **Infrastructure**: 80% or higher
- **CLI/GUI Client**: 60% or higher (supplemented by E2E)

### Exceptions
- Boilerplate code (getter/setter)
- Simple wrappers around external libraries (pass-through only)
